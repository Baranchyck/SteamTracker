# Steam Tracker — специфікація MVP

## 1. Технологічний стек

| Шар | Технологія |
|---|---|
| Застосунок | C#, .NET, настільний застосунок (Windows) |
| Графічний інтерфейс | WPF (XAML) |
| Робота з даними | ADO.NET (Microsoft.Data.Sqlite) |
| База даних | SQLite (локальний файл) |
| Виклики Steam Web API | HttpClient |
| Контроль версій | Git + GitHub, робота в гілках, злиття через pull request |
| Тестування | MSTest / xUnit / NUnit |
| CI | GitHub Actions — збірка та тести на кожен push/PR |

**Чому SQLite:** застосунок локальний і однокористувацький, тому окремий сервер БД не потрібен. База — один файл поруч із застосунком, без встановлення та налаштування. Використовується для збереження SteamID64 і кешу відповідей API.

**Критерій відбору фіч у MVP:**
- Дані отримуються одним-двома викликами офіційного Steam Web API.
- Немає залежності від приватної фінансової інформації користувача.
- Не потрібен фоновий процес з накопиченням історії у часі.

## 2. MVP — мінімально життєздатний продукт

**Мета MVP:** користувач входить через Steam, обирає гру зі своєї бібліотеки і бачить, які незакриті ачівки найпростіше отримати наступними. Це єдиний наскрізний сценарій, який доводить цінність продукту. Усе інше винесено за межі MVP (розділ 3).

### 2.1 Авторизація через Steam
- Вхід через Steam OpenID: застосунок відкриває системний браузер на сторінці логіну Steam, локальний `HttpListener` на localhost приймає перенаправлення з підтвердженням.
- Отриманий SteamID64 зберігається в SQLite для наступних запусків (повторний вхід без логіну).
- Ключ Steam Web API не зберігається у відкритому коді — виноситься в конфігурацію поза контролем версій.

### 2.2 Базовий профіль
- `ISteamUser/GetPlayerSummaries` — нікнейм, аватар, рівень приватності.
- Приватний профіль обробляється як окремий стан інтерфейсу, не як помилка.

### 2.3 Планувальник досягнень (ядро MVP)
- `GetOwnedGames` — список ігор користувача для вибору гри.
- `GetPlayerAchievements` — закриті та незакриті ачівки обраної гри.
- `GetGlobalAchievementPercentagesForApp` — глобальний % отримання по кожній ачівці.
- Незакриті ачівки відображаються списком, відсортованим за глобальним відсотком (найбільш масові — першими).
- Глобальний % не є мірою складності ачівки — в інтерфейсі це позначається окремо.

### 2.4 Мінімальний UI
- Одне головне вікно з двома екранами: вхід → профіль і вибір гри → список ачівок.
- Асинхронні запити з індикатором завантаження.
- Окремі стани для помилок API, відсутності мережі та приватного профілю.

### Що НЕ входить у MVP
Розрахунок «скільки ачівок до +N% проходження», друзі, лідерборди, Co-op Matchmaker, аналітика бібліотеки, кеш з політикою інвалідації — див. розділ 3.

## 3. Функціональність після MVP (наступні ітерації)

### 3.1 Розширення планувальника досягнень
Розрахунок, скільки ачівок потрібно закрити, щоб підняти % проходження гри на N пунктів.

### 3.2 Порівняння часу гри з друзями
- `GetFriendList` — список друзів.
- `GetOwnedGames` по кожному другу (паралельно, обмежено через `SemaphoreSlim`) — `playtime_forever` для обраної гри.
- Лідерборд, позиція користувача, % від середнього, список друзів без цієї гри.
- `playtime_2weeks` — окремий індикатор поточної активності.

### 3.3 Друзі-радар
- `GetFriendList` + `GetPlayerSummaries` (batch до 100 SteamID) — `personastate`, `gameid`, `gameextrainfo`.
- Фільтр «вільні зараз» (online / in-game, без offline і away).

### 3.4 Co-op Matchmaker
- Список SteamID → `GetOwnedGames` по кожному → перетин бібліотек.
- Сортування спільних ігор за середнім playtime групи.
- Фільтр підтримки кооп-режиму не входить — потребує тегів гри з неофіційного `appdetails`.

### 3.5 Використання бібліотеки
- `GetOwnedGames` — playtime по всій бібліотеці, виявлення ігор з `playtime_forever` близьким до нуля.
- Розрахунок вартості за годину не планується: залежить від неофіційного `appdetails` і поточної (не історичної) ціни покупки.

### 3.6 Єдина навігація
Навігація між усіма модулями в одному вікні без перезапуску.

## 4. Нефункціональні вимоги

- **Продуктивність.** Мережеві виклики асинхронні, інтерфейс не блокується.
- **Надійність.** Недоступність API, відсутність мережі чи приватний профіль обробляються без аварійного завершення застосунку.
- **Безпека.** Ключ API поза репозиторієм; вхідні дані (наприклад, SteamID) валідуються; SQL-запити параметризовані.
- **Зручність використання.** Одне головне вікно.
- **Портованість.** Цільова платформа — Windows.
- **Тестованість.** Логіка роботи з API та даними відокремлена від коду UI.

| Швидкий запуск гри | `steam://run/{appid}` | — |

## 6. Технічні ризики

- **Приватність профілів.** `GetOwnedGames` / `GetPlayerAchievements` повертають порожні дані при закритих Game Details — обробляється як окремий стан, не як помилка чи нуль.
- **Rate limits.** ~100 000 запитів/добу на ключ. Паралельні виклики (перелік друзів, у наступних ітераціях) обмежуються `SemaphoreSlim`.
- **Зберігання ключа API.** Не комітиться в репозиторій; user secrets на розробці, конфігураційний файл поза контролем версій на збірці.
- **Файл SQLite.** Не комітиться в репозиторій (додається в `.gitignore`); схема створюється застосунком при першому запуску.
